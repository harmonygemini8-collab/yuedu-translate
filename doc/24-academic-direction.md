> 依据：竞品与切入方案 `I:\Project\Translation\translation-extension-plan.md`（仓库外，2026-10-28 修订版）及一次用 arXiv 论文做的实测报告。本文记录**方向怎么变了、做到哪一步、哪些还没做**。

## 1. 方向变更

| | 之前（01、21） | 现在 |
|---|---|---|
| 目标用户 | 泛英文网页读者：开发者、学生与研究人员、知识工作者 | **首发楔子：学术论文阅读者**（高校、研究所、留学生），其余用户顺带 |
| 对外卖点 | 保留原文的双语对照；生词连同它在这句话里的意思一起查 | 在此之上加上「**公式不崩、术语不乱、引用与脚注不拆句**」 |
| 优先级 | 网页 → 视频字幕 → 输入框 | **论文网页（arXiv HTML/ar5iv）→ 术语一致 → 表格与参考文献 → PDF** |

选择学术方向的理由（来自方案第三、九节）：场景封闭（论文站点 + PDF）、痛点可量化（公式、术语、表格）、付费意愿相对高。方案同时提醒：术语本身不是它的差异化楔子（对手已有"先分析全文再翻译"），真正拿得出手的是**免费承诺不缩水、长页不卡、自带 Key 全功能、不审查**；学术人群的卖点写成「读论文不卡、公式不崩」。这一点以方案原文为准，本文不展开。

不变的约束：免费层即完整产品；Key 只存本地；账号、同步、团队、支付是服务端能力。**PDF 暂不做**：先把 HTML 论文做到可对外推荐，否则 PDF 只会把同样的毛病原样带过去。

## 4. 已知限制（对外不要承诺的）

- **只在 arXiv 的 HTML 版（ar5iv）上测过**，且是人工在浏览器里看。KaTeX、MathJax 页面按结构支持，没有真实页面验证。
- 占位符靠翻译引擎"原样带回"：谷歌免费接口实测可行，微软与大模型服务理论上也可，**未逐一实测**；偶尔被吞或改坏，已有两层兜底（宽容还原、不带占位符重翻），但极端情况仍会出错。
- 引用在译文里是普通文字，不是可点击的链接。
- 术语锁定只处理「大写开头的多词术语」，且依赖该术语单独翻译一次的结果，这个单独的翻译有时也不准（如 QNLI 那样的缩写不在此列）。
- 朗读译文时，公式的文字也会被读出来。
- 上下标在所有网站一律保留原样，H₂O、10ᵗʰ 之类偶尔会被引擎在周围加空格。
- 全大写的缩写（含 AI、CPU）在整句正文里一律不翻；整句都是大写的标题不受影响。
