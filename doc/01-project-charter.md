# 01 项目目标说明书

> 文档编号：PROJECT-001 ｜ 版本：v0.1 ｜ 状态：待评审

## 1. 项目背景

用户阅读外文网页时，通常只能在以下方式中选择：

- 只看原文，阅读速度慢；
- 整页替换为译文，不便核对原文；
- 复制到外部翻译工具，打断阅读流程。

阅渡（Yuedu Translate）是一款 Chrome 扩展，在尽量保留网页结构和交互的前提下，提供段落级双语对照阅读。产品方向参考沉浸式翻译，但采用独立品牌、界面与实现，首版不以复刻其全部功能为目标。

## 2. 产品定位

> 面向经常阅读英文网页的中文用户，提供低干扰、可核对、操作简单的双语阅读工具。

**品牌释义：**通过阅读，渡过语言障碍；保留原文，帮助理解。

**正式中文展示名称：**阅渡 · 双语对照翻译。

**英文展示名：**Yuedu Translate（采用“阅渡”的拼音，不使用未确认的 Readora）。

**现有宣传语：**原文在眼前，理解在身边。

> **2026-10-28 方向调整**：首发楔子改为学术论文阅读者，卖点加上「公式不崩、术语不乱、引用与脚注不拆句」。上面的定位语与宣传语暂不改，对外文案等 P1 做完再统一；详见 [24 学术阅读方向与进度](./24-academic-direction.md)。

### 首批目标用户

- 阅读英文技术文档的开发者；
- 阅读外文文章的学生与研究人员；
- 阅读海外资讯的知识工作者。

### 首版典型场景

技术文档、博客文章、新闻和知识类长文，以及结构相对稳定的普通 HTML 页面。

## 3. 项目目标

| 编号 | 目标 | 达成判断 |
|---|---|---|
| G-01 | 建立完整双语阅读闭环 | 用户能启动翻译、阅读译文、停止任务、恢复原文 |
| G-02 | 保持网站基本可用性 | 测试页面中的链接、按钮与原有阅读操作正常 |
| G-03 | 控制翻译成本 | 具备配额、限流、幂等、预算告警及服务熔断 |
| G-04 | 建立商业服务基础 | 具备账号、身份校验、权益和用量记录 |
| G-05 | 建立隐私与安全基线 | 平台密钥不进入扩展，上传文本有明确告知 |
| G-06 | 验证商业可行性 | 邀请试用后取得使用反馈、真实成本和付费意愿证据 |

首版成功的标准不是“功能数量接近竞品”，而是核心阅读体验稳定、用户愿意持续使用、成本可控。

## 4. 非目标

首版不承担：

- PDF 保留排版翻译；
- 图片 OCR 和漫画翻译；
- 视频字幕、实时会议与语音翻译；
- 输入框、划词和悬停翻译；
- Chrome 以外浏览器与移动端；
- 团队协作与企业管理；
- 对所有网站、所有语种的兼容承诺。

## 5. 项目约束

| 类别 | 约束 |
|---|---|
| 浏览器 | Chrome 桌面版，最低版本在技术验证阶段确定 |
| 扩展规范 | Manifest V3；所有执行逻辑随安装包发布，不加载远程代码 |
| 语言方向 | 默认英语 → 简体中文 |
| 翻译服务 | 平台统一提供，经平台后端调用 |
| 开发方式 | 先需求与设计评审，再实现 |
| 发布方式 | 邀请试用通过后进入正式收费 |
| 费用 | 预算和供应商确定前，只使用本地模拟服务，不开通付费资源 |

## 6. 发布里程碑

| 里程碑 | 内容 | 是否收费 |
|---|---|---|
| MVP-A 邀请试用版 | 网页双语阅读、最小账号、平台翻译后端、配额与成本监控、隐私告知 | 否 |
| MVP-B 公开商业版 | 在 MVP-A 验证通过后接入订阅与支付，完成正式上架 | 是 |
